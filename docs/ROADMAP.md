## 2026-08-04 (cont.) — Script generator: "Refine with AI" iterative editing loop

**DONE (commit 22767bd).** The persona script panels (`earnings_page._render_persona_steps` → `render_draft_box`) could only **Generate** (a cold draft from the Stage-1 numbers + the "What's new"/notes fields) and **Submit**. After editing a draft there was no way to ask the AI to revise it — clicking Generate again started over and silently discarded the edits. Added a conversational **refine loop**: a new **`_refine_persona_draft(current_text, instruction, role, ss)`** revises the CURRENT (possibly hand-edited) draft per a free-text instruction, in place, and a **"Refine" instruction box + button** now sits beside Submit on every persona panel (reads `box.value`, re-runs the pacing estimate, iterative — the box stays for repeated nudges). **Guardrails hardened to OVERRIDE the instruction** (the no-fabrication directive [[cfa-level-financial-analysis]]): never adds/changes a figure already in the draft, never introduces a beat/miss/consensus comparison unless already present (silently drops that part of the instruction if asked), inserts a `[placeholder]` for a fact the instruction doesn't supply, but DOES incorporate a specific fact the user explicitly provides (a named customer) phrased plainly. **No keyword fallback** — a heuristic can't follow an instruction, so with no API key it returns the draft unchanged and says refine needs the key. **"Generate with AI" is now guarded** — with an existing draft it asks "Regenerate from scratch?" before overwriting, pointing at Refine as the non-destructive path. Verified live on NLKP demo (Refine condensed a 901-char CFO review to one sentence, all figures intact; confirm dialog fired; Regenerate restored the full draft) + unit tests (false "beat consensus" dropped, user-supplied customer name kept, figures protected). smoke 44/44. **Origin:** user observed there was no post-edit regenerate and asked how a user could give instructions.

## Praxis Consensus — the model (decided + engine built 2026-07-18)

Core IR-workflow principle: **our OWN consensus, rolled up from the analyst models we collect, is the TRUE consensus** — because we've seen each model we catch the dispersion a "rough analyst" creates, which the street's black-box mean hides; a big IR job is keeping the street from drifting out of line. Engine: `core/consensus.rolled_consensus(period, client_id, include_street=)`. User's decisions: **headline = MEDIAN** of received models (robust to outlier; mean+range shown alongside); **fallback = period-verified street aggregate, labeled provisional**, below coverage threshold; **outliers auto-flagged only** (>10% off median, kept in the math — no manual exclude). Coverage = models received / active covering analysts; authoritative at ≥2 models & ≥50% coverage. Precedence: model roll-up → street (provisional) → `q2_consensus_rev` override → none. Always returns a **reconciliation** (model-median vs street %) so IR can see drift. Thresholds are tunable params.
